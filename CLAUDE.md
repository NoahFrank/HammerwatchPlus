# HammerwatchPlus: agent instructions

The HoH2 game-modding-playbook project (`~/.claude/playbooks/game-modding-playbook.md`,
copied to `docs/PLAYBOOK.md` at P8). README.md holds the status and the phase checklist.
Update both README.md and `docs/RE_NOTES.md` at the end of every work session.

## Hard rules
- **GameLab only.** Boot the game through `python -m gamelab run <scenario> --mode lab`.
  Never start the user's install directly, and never touch their `HWR2.exe.cfg`, Steam
  cloud saves, local saves, `%LOCALAPPDATA%/HeroesofHammerwatch2` or install `res/`.
  The launcher asserts all of this and marks a run INVALID when it is violated.
  If the user specifically requests otherwise then you may bend the this rule, 
  but otherwise hold steadfast.
- **No real input.** No `SendInput`, `keybd_event`, `mouse_event`, `SetCursorPos`,
  `SetForegroundWindow` or `bring_to_front`. Input is `PostMessage` to the game window,
  or a `gl <id> <verb>` console command answered by `mods/gamelab-probe`.
- **Exit codes are refusals, not warnings.**
  - 3: build mismatch. Re-dump, then `tools/pin_build.py --reason`.
    `--accept-build-drift` is a one-run override and stamps the run.
  - 4: lock held or dirty teardown. Find out why, then `python -m gamelab reset`.
  - 5: INVALID.
  - 2: preflight failed.
  - 6: TIMEOUT (the scenario's deadline passed; what was collected is kept).
- **Label claims verified vs assumed.** A fact is verified only when measured on the
  pinned build: a GameLab run, a log line or the decompiled source. Cite it.

## Where things are
- Game scripts: `gamecode/sdk/hoh2/scripts/` (AngelScript, regenerated by `tools/bootstrap.py`).
- Data: `gamecode/datatables/*.sval.json`, as parsed by the game.
- Mods: `mods/<id>/`. The id is the folder name. Mods are enabled per save via
  `gamelab/hps.py` (HashString = MurmurHash3_x86_32, seed `0xf808409c`).
- Mod module constructors run when the menu level (`levels/town.lvl`) loads.
  `UpdateFrame` ticks only after a session starts (`docs/RE_NOTES.md`, mod lifecycle).
- Log paths and the mod stack: `docs/MODDING_NOTES.md`. Hooks: `docs/hooks.md`.
- Mod conventions: `docs/modules.md`.
- Run outputs: `gamelab/results/<time>-<scenario>-<mode>/`.
  - `run.json`: verdict and assertions.
  - `gl.jsonl`: telemetry.
  - `logs/`, `shots/`.
- Every gl verb, with its doc comment: `docs/generated/verbs.md`, generated by `tools/list_verbs.py`
  (`--check` fails when it is stale).
- Adding a probe: a `RegisterVerb` in `mods/gamelab-probe/scripts/GameLab/Probe.as`.
  Read-only, capped, reports truncation. Then a `{"do": "gl", "verb": ...}` scenario step,
  and re-run `tools/list_verbs.py`.
