# MECHANICS — Heroes of Hammerwatch II (pinned build 25509441, log `Build 170`)

How the game works, for mod authors and for the Pilot (P6b). **Every claim cites
either the decompiled source on the pinned build or a GameLab run**, so it is
verified in the CLAUDE.md sense. Source paths are relative to
`gamecode/sdk/hoh2/scripts/` (regenerated by `tools/bootstrap.py`). Runs are
`gamelab/results/<id>/`.

The seed was hh2-data-mine's `ARCHITECTURE.md` (2026-01 assets). Nothing was carried
over uncited. Where the seed and the pinned build disagree, the build wins.

## 1. Gameplay loop (the one the Pilot plays)

```
town (hub) ── mission board / map shop ──► loadout menu ──► mission level 0
   ▲                                                         │ NextLevel (m_idNext / i+1)
   │                                                         ▼
   └── MissionEndMenu (rewards, revive cost) ◄── last level: Succeeded │ death: Failed │ quit: Aborted
```

| Step | What happens | Source |
|---|---|---|
| Pick a mission | Mission board / map shop / survival shop call `MissionManager::SetMission(id, randi(), slot, ilvl)`. The reward seed is random per pick. | `Town/MissionShopContent.as:30`, `Town/MissionMapShopContent.as:28`, `Town/MissionSurvivalShopContent.as:40`, `GUI/MissionLoadoutMenu.as:586` |
| Loadout | Opening the loadout menu **resets the run** (`plr.ResetForNewMission()`, run flags cleared). | `GUI/MissionLoadoutMenu.as:207-209` |
| Start | `StartMission()` sets state `Running` on every peer and `ChangeLevel`s to `m_levels[m_missionLevelIndex]`. | `Missions/MissionManager.as:53-69` |
| Next floor | `NextLevel(id)` finds the level by id and starts it. With no such level, the mission ends `Succeeded`. `NextLevel()` follows the current level's `m_idNext`, which `MissionDef` fills from the next array entry when it is not authored. The last level's default is `"end"`, which matches no level, so the mission ends `Succeeded`. | `Missions/MissionManager.as:156-178`, `Missions/MissionDef.as:126-134` |
| End | `AbortMission(state)` (server only) sets the state on every peer and `ChangeLevel("levels/town.lvl")`. | `Missions/MissionManager.as:83-95` |
| Death | When the party is dead, `DeadMenu` calls `AbortMission(Failed)`. | `GUI/DeadMenu.as:89` |
| Back in town | `TownGameMode` opens `MissionEndMenu` when the record's state is Succeeded, Failed or Aborted. | `GameModes/TownGameMode.as:28-29` |
| Success rewards | On the transition to `Succeeded`: `MissionDef.GetReward(seed)`. If the reward has `m_ngp`, it raises `ngp` and the town's `m_ngp`. It also sets the town and character flags and gives `m_experience.x`. | `Missions/MissionManager.as:99-135` |

**Measured** (`mission-enter`, run 20261017-140945): `gl mission story_intro_find_npcs 0`
(the same `SetMission` + `StartMission`) takes the paladin from town to
`levels/generated.lvl` in phase `mission`. The player record survives the level load,
and the player unit is re-spawned.

**Measured** (runs 20261017-140911 and 20261017-144111): a character quit inside a
mission keeps a level save. Picking it again opens the `run-resume` dialog: Yes resumes
the run, No goes to town. Source: `GUI/PickCharacterWindow.as:348-357`. GameLab's
`pick <i> [town|resume]` answers it through the same handler.

## 2. Progression

| Mechanic | Rule | Source |
|---|---|---|
| XP to next level | `ExperiencePerLevel * level^ExperienceExponent` = `2000 * L^2.2` | `Behaviors/Actors/Player/PlayerRecord.as:2077-2080`, `Data/Player.as:99-100` |
| XP gain multiplier | `ExperienceMul` stat × buffs × `ExperienceScale` (1.0) × multiplayer scale × a level-difference factor, then `roll_round` | `PlayerRecord.as:2296-2305`, `Data/Player.as:97-98` |
| Level-up loop | Adds XP level by level until the cap. Overflow carries. Each level-up shows the `levelup` tutorial and `OnLevelUp`. | `PlayerRecord.as:2327-2360` |
| Level cap | `LevelCap + ngp * LevelCapNGPAdd` = `20 + 5·ngp` (10 in the demo build) | `PlayerRecord.as:2276-2279`, `PlayerRecord.as:2318-2321`, `Data/Player.as:72-73` |
| Equipment drop level cap | `max(levelCap + 5, level + 10)` | `PlayerRecord.as:2281-2284` |
| Unique drop ilvl | `min(dropCap, max(1, round(g_diffLevel) + randi(3) - 1))` | `Items/LootTable.as:389` |
| New Game+ | A successful mission whose reward has `m_ngp` raises the character's `ngp` (if `g_ngp >= ngp`) and the town's `m_ngp`. NG+ adds enemy move speed/budget ×1.25, material gain +0.2 per level, and +3 elixirs per NG+. | `Missions/MissionManager.as:110-122`, `Data/Player.as:54-64` |
| Stats from attributes | 5 HP per VIT, 5 mana per FOC, 2 armor per STR, 0.05 HP regen per VIT, 0.1 mana regen per FOC | `Data/Player.as:3,37-41` |
| Bonus stat points | Effect `GiveStatPoints` adds to `bonusStatPts` | `Behaviors/Effects/GiveStatPoints.as:34` |
| Town progression | Buildings are placed on plots via `TownRecord.AddBuilding(def, plot, variation)`; costs are a `ShopCost` per variation | `Town/TownRecord.as:100-112`, `Town/BuildingDef.as:7,28,132` |

**Measured:** the `town-paladin` fixture reads back `player.level` = 1 on a fresh character
(every fixture run, e.g. 20261017-141949). The `town-tavern` fixture builds a tavern through
`AddBuilding` and reads back `buildings.tavern` = 0 (variation), and `inspect town buildings`
returns it (run 20261017-141949).

## 3. Loot

| Mechanic | Rule | Source |
|---|---|---|
| Pool roll | Each `LootTablePool` rolls `n = randi(1000)` and walks its entries subtracting `m_chance`. The first entry that takes `n` below 0 drops, so chances are per-mille and a pool summing to ≥ 1000 always drops. | `Items/LootTable.as:134-137` (also `:156`, `:190`) |
| Entry kinds | Plain string = simple item. Array tagged `material`/`trinket`/`unit`/`prefab`/`item`/`unique`/`effect`/`valuable`/`elixir`. A dictionary = generated equipment. | `Items/LootTable.as:96-125` |
| Material amount | `randi(max - min) + min`, i.e. `min .. max-1` | `Items/LootTable.as:483,493` |
| Valuables | Picking up a valuable gives its price in **gold** immediately and records it in `valuableInventory` | `PlayerRecord.as:2141-2145` |
| Trinkets | Go to `trinketInventory`, which is cleared at the start of each run | `PlayerRecord.as:2133`, `PlayerRecord.as:2008` |

**Measured:** `open-chest` (run 20261017-140030) spawns `items/chests/cache_bronze.unit`,
presses Use and checks the material gain is one the chest's own pools can produce
(`gamelab/loot.py explain`). Pools 1-4 of `cache_bronze` sum to 1000, so they always drop.
Loot is **not seeded** (`randi`), so exact drops are only checked against the table.

## 4. Economy (materials)

Seven materials: Gold 0, Wood 1, Stone 2, Iron 3, Crystals 4, Dust 5, Ore 6
(`Behaviors/Effects/GiveMaterial.as:1-12`).

| Mechanic | Rule | Source |
|---|---|---|
| Two wallets | `PlayerRecord.GiveMaterial`: outside town it changes the **character's carried** `materials[]`, scaled by the material gain modifier and `roll_round`. In town it goes to the **town** (`g_myTownRecord.GiveMaterial`, unscaled). | `PlayerRecord.as:2561-2608`, `Town/TownRecord.as:311-320` |
| Banking a run | `MissionEndMenu` sums the reward steps: carried materials (gold minus the valuables' value), valuables, trinkets (only with a `magic_shop` building), the mission reward and the revive cost. It pays the total into the town, then **zeroes the character's carried materials**. | `GUI/MissionEndMenu.as:196-300`, `GUI/MissionEndMenu.as:428-442` |
| Trinket conversion | Common 1 crystal, uncommon 3 crystals, rare 1 dust, epic 3 dust (needs the magic shop) | `GUI/MissionEndMenu.as:213-262` |
| Revive cost | On Failed/Aborted, a negative step of `costMul` × the total. With no modifiers, `BaseReviveCost` 0.4 means **40% of the run's haul is lost**. | `GUI/MissionEndMenu.as:265-288`, `Data/Player.as:75` |
| Spending | Shops and buildings charge a `ShopCost`. The Thunderbird deducts gold/wood/stone/iron from the carried materials. | `Town/BuildingDef.as:7`, `Behaviors/Thunderbird.as:87-90` |

**Measured:** the `inv` probe reports `store: "town"` in town and `store: "character"` in a
mission (runs 20261017-141949 and 20261017-140945), the two wallets of `GiveMaterial`.

## 9. Script-lifecycle facts mods depend on

| Fact | Evidence |
|---|---|
| A level load rebuilds every module **and** reloads the script module, so all mod globals reset | `mission-enter` run 20261017-140911: probe `boot n=1` again, `cmds` 5 → 1 |
| A level load does **not** recompile scripts from disk; a restart does | `reload-mark` run 20261017-144317 |
| The town starts `StartGame` with a null save, so `Module.Load` never runs in town; town data comes from `PersistentSaves::GetTown` | `docs/RE_NOTES.md` (mod lifecycle); `GameModes/AGameplayGameMode.as:782-821` |
| `GetVarFloat` returns 0 for int cvars, so read cvars by `GetVarType` | `null-payload` run (17 cvars read back) |
| AngelScript `try { } catch { }` works; the catch gets no exception info | `probe-selftest` (`selftest-throw`) |
