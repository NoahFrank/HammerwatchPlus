# GameLab `gl` verbs

Generated by `tools/list_verbs.py` from the `RegisterVerb` calls; do not edit by hand.
Send one as `gl <id> <verb> args` (a `{"do": "gl", "verb": ...}` scenario step, or
`Pilot.cmd` from a bot). Measurement-only verbs say so in their description.

## gamelab-hands

| verb | args | what |
|---|---|---|
| `spawn` | `<unitFile> <dx> <dy>` | spawn <unitFile> <dx> <dy>: produce a unit at the player's position + (dx, dy), the same UnitProducer.Produce call level scripts and actions use |
| `pick` | `[index] [town\|resume]` | pick [index]: play the index-th character of the open PickCharacterWindow, through the window's own handler (OnFunc "play <key>"), like a click on Play. |
| `mission` | `<missionId> [floorIndex]` | mission <missionId> [floorIndex]: what the mission board's start does (MissionManager::SetMission + StartMission); floor 0 when omitted. |
| `build` | `<buildingId>` | build <buildingId>: what the town builder's "new" does (BuildingBuilderContent.Buy, Town/BuildingBuilder.as) minus the cost and the cutscene: AddBuilding on a buildable plot of the building's plot type (the first, where the game picks one at random), then SavePlayerAndTown |
| `save` |  | save: the game's own SavePlayerAndTown (what the builder, the shops and leaving town call), so the next session loads this town instead of a null one |
| `xp` | `<amount>` | xp <amount>: PlayerRecord.GiveExperience (kills, mission rewards), gain modifiers skipped |
| `material` | `<type> <n>` | material <gold/wood/stone/iron/crystals/dust/ore> <n>: PlayerRecord.GiveMaterial (pickups) |
| `charflag` | `<name>` | charflag <name>: PlayerRecord.SetCharFlag (mission rewards set these) |
| `assign` | `<str\|dex\|int\|foc\|vit> <n\|all>` | assign <str/dex/int/foc/vit> <n/all>: the attribute assigner's Buy("assign") (Town/AttributeAssignerShopContent.as:10-31), once per point, while points are placeable |
| `upgrade` | `<shopId> <upgradeId> <step>` | upgrade <shopId> <upgradeId> <step>: what an upgrade shop's Buy("buy") does (Town/UpgradeShop.as:139-150: SetShopUpgradeLevel, RefreshModifiers) minus the cost; e.g. upgrade apothecary potion-charges 0 = the first potion charge |
| `equip` | `<baseItemId> <quality> [ilvl]` | equip <baseItemId> <qualityMask> [ilvl]: Equipment::Generator.GenerateItem (the spawnequipment cheat's path, Console/Cheats.as), then equipped.Equip like a new character's starting gear (PlayerRecord.as:451-465). The quality is the generator's: its RollQuality tests `mask & Common != 0`, which binds as `mask & (Common != 0)`, so a mask without the Common bit rolls nothing and the base item's quality is used (EquipmentGenerator.as:15; measured fixture-ranger 20261017-151727: rare asked, 2 given). The reply carries the quality actually given. Equip refusing (MayEquip: level or attribute requirements) returns the item itself, and fails the verb. |
| `timescale` | `<x>` | timescale <x>: measurement only, NOT a test accelerator. Sets the engine cvar g_timescale (0.1-16), turning e_cheats on first. Game-ms timers scale with it but player movement per frame does not (floor-soak 20261017-175501 at 4x: intents timed out after a quarter of the walk), so gameplay results under it are not results at 1x. |
| `cull` |  | cull: the cht_kill_all cheat's body (Console/Cheats.as:970-980): Kill every targetable actor not on the player's team. Measurement scenarios only, like teleport. |
| `teleport` | `<x> <y>` | teleport <x> <y>: set the local player's unit position (the respawn path's call, Player.as SetPosition(x, y, z, true)). Measurement scenarios only: a gate scenario that teleports is not evidence of play. |
| `controller` |  | controller: the live GameInput the player reads (g_gameMode.m_currInput), read-only |
| `input` | `<ms> <mx> <my> [aimX aimY] [button,button]` | input <ms> <mx> <my> [aimX aimY] [button,button]: hold an emulated stick/buttons for ms of gameplay frames. Replies at once; "input_done" (same id) when the hold ends. |

## gamelab-pilot

| verb | args | what |
|---|---|---|
| `pilot` | `<intent\|pause\|resume\|step\|target\|stop\|status\|reflex> [args] [until=..] [timeout=ms]` | pilot <intent/pause/resume/step/target/stop/status/reflex> [args] [until=..] [timeout=ms]: start an intent (path_to, move, exit, attack, kite, use, potion, wait) that runs in-engine until done or an `until` interrupt, ending in a "pilot" event; or control the running one; `reflex potion=<hp%> fire=<radius>` sets standing orders. Python client: gamelab/pilot.py. |
| `scan` | `[radius]` | scan [radius]: the scene sorted into what a player acts on. Every category names the field it comes from, and "raw" is the unfiltered unit list (count + first SCAN_CAP). |
| `pathfind` | `x y [diameter] [maxDistance] [maxRange] [fromX fromY]` | pathfind x y [diameter] [maxDistance] [maxRange]: the engine pathfinder's answer from the player, read-only (nodes, length, first and last node) |
| `reachmap` | `x0 y0 x1 y1 step` | reachmap x0 y0 x1 y1 step: read-only grid of Pathfind answers from the player, one row string per y ("#" a path, "." none, "@" the player's cell). Capped at REACHMAP_CAP cells. |
| `exitareas` | `[radius]` | exitareas [radius]: read-only. The nearest enabled exit's script object (its Areas: a LevelExitAreaNext fires only for a player inside one), whether the player is inside each, and the sensor units around the exit unit (QueryCircle getSensors), capped at SCAN_CAP. |
| `routesweep` | `[spacing] [offset]` | routesweep [spacing] [offset]: read-only. The exit route from the player (RouteExit, as the exit intent plans it), then RouteExit again from points spaced along that route and offset to both sides of it: where a player might be after a fight or a knock-back. Per point: answered, partial, escaped, NavRoute expansions. Points a solid body covers (blocked) or the player's floor does not reach (offFloor) are counted, not routed. No walking: every route is planned in this one call. |
| `bodies` | `<x> <y> [step]` | bodies <x> <y> [step]: read-only. Every 'step' units (default 16) from the player to x,y: the collision bodies a player-sized circle overlaps (QueryCircle, sensors excluded), actors flagged; Walkable (nav) and PathOk (raycast) per point. Unit ids deduplicated, capped at SCAN_CAP. What stands in a passage the nav graph says is closed. |
| `breakables` | `[radius]` | breakables [radius]: read-only. Breakable units within radius (default 400) of the player, nearest first: unit, name, x, y, d. Capped at SCAN_CAP, truncation reported. |
| `exitprobe` | `[refX refY]` | exitprobe [refX refY]: read-only. Whether the nearest exit's stand point is joined to the floor the player is on: Walkable(stand); per ring radius, a 16-bit string of PathOk(stand -> ring point) and of PathOk(player -> ring point); NavRoute both ways (expansions, answered). |
| `pfsweep` | `<dx> <dy> <steps> [diam...]` | pfsweep <dx> <dy> <steps> [diam...]: read-only. For each diameter (default 12), whether Pathfind from the player to player + k/steps * (dx,dy) answers, k = 1..steps; one bit string per diameter ("1" answered). Separates "too far" from "blocked" from "too wide". |
| `pfbench` | `<n> <dx> <dy> [preN preDx preDy]` | pfbench <n> <dx> <dy> [preN preDx preDy]: read-only. n identical Pathfind calls in one frame, from the player to player + (dx,dy), after preN calls to another offset; how many answered and the first that did not (a per-frame budget shows as answers stopping partway). |

## gamelab-probe

| verb | args | what |
|---|---|---|
| `ping` |  | ping: liveness; the probe version, phase, boot count, level and commands served. |
| `multi` | `<verb> [args] + <verb> [args] ...` | multi <verb> [args] + <verb> [args] + ...: run each sub-command in this frame, the k-th replying under id "<id>.<k>", then one reply under <id> with the count. One typed line instead of one per probe: a fixture readback is 16 probes (session.gl_multi). |
| `help` |  | help: every registered verb and its argument signature. |
| `state` |  | state: phase, level, open window and the local player (class, level, hp, position); fixtures read back through it. |
| `mods` |  | which resource mods the running game sees and has enabled: the live half of the environment check (gamelab/env/environments.json "mods") |
| `ui` |  | open windows, bottom to top, by script class |
| `overlays` |  | overlays: everything drawn over the world at this moment, so a scenario can require the set to be empty or expected (repro playbook 1.3). Windows (bottom to top), the tutorial panel (Tutorials::TutorialModule.m_showing, drawn by HUDTutorials), live announce / loot-log entries (HUDAnnounce subclasses, style id + text) and the boss bar. HUD notifications are not listed: HoH2's AddNotification is a stub ("TODO: Add notifications", WorldScript/GUI/AddNotification.as). |
| `buildings` |  | buildings: the current town record's buildings (id -> variation), as the town builder and the gambler read them (TownRecord.GetVariationOnBuilding) |
| `clock` |  | clock: scene time (g_scene.GetTime(), what behaviours time themselves with), the probe's own frame count, and the time-scale / hour cvars |
| `widgets` | `[depth]` | widgets [depth]: the UI widget tree of every open window and the HUD, capped, with truncation reported. |
| `terrain` | `[radius] [step]` | terrain [radius] [step]: occupancy grid around the player from the game's own point query (g_scene.QueryRect(pos, 1, 1, ~0, RaycastType::Any), the test SpawnPrefab uses for "can something stand here"). Rows north to south: '.' free, '#' blocked, '@' the player. At most TERRAIN_CELLS x TERRAIN_CELLS; "truncated" when clipped. |
| `members` | `<TypeName>` | members <TypeName>: the script type's properties (name + type) through the engine's reflection (Reflect::GetType / TypeInfo.GetProperties). Read-only by construction: it never touches an instance. Capped at MEMBERS_CAP; reports truncation. |
| `inspect` | `<player\|town> [dotted.path]` | inspect <player/town> [dotted.path]: read-only. A field of the player or town save record by dotted path, JSON-encoded, capped. |
| `selftest-throw` |  | selftest-throw: dereferences null on purpose; proves ConsoleGl's catch (playbook 1.4) |
| `classes` |  | player classes the fixture recipes can name |
| `cvars` | `<name>...` | cvars <name>...: values as the running game holds them (the loaded settings, not the file on disk); the launcher's mute check reads snd_volume* here |
| `inv` |  | inv: materials as the game reads them (PlayerRecord.GetMaterial: the town's store while in town, the character's own on a mission) |
| `near` | `[radius] [behaviorOrUnitName]` | near [radius] [filter]: units within radius (default 200) of the player, nearest first, capped at NEAR_CAP; "truncated" reports how many were left out |
| `usables` |  | usables: what the player could interact with right now, top (the one Use acts on) first |
| `sval` | `<file.sval>` | sval <file.sval>[:entry]: read-only. A datatable as the game parsed it, as JSON, sent in parts when long. |
| `char` | `<classId> <name>` | fixture verb: char <classId> <name> The same steps as CreateCharacterWindow's "create" (GUI/CreateCharacterWindow.as), minus the portrait/colour pickers, which CreateCharacter defaults. |
